LeCHOW

Agile Sprint Plan

7 sprints · Recommended 2-week cycles · Agile methodology

Week 1
Week 14
1
Sprint 01 · Weeks 1–2
Foundation: Auth & Customer Registration
Core

Everything else depends on knowing who the user is. Build registration, login, and verification before a single order is placed.

◆Registered customer signup with first_name, last_name, email/phone
◆Verification code flow + isVerified boolean toggle
◆Login session management and protected routes
◆Address and contact method selection (email or phone)
◆Owner account bootstrapping — first Owner{} seeded in DB
◆Basic customer profile view and edit
Testable by Registered customers can sign up, verify, and log in.
2
Sprint 02 · Weeks 3–4
Core Ordering (Registered Customers)
Critical path

The heart of LeCHOW. Build product browsing, cart, and full order submission so the Order schema is exercised end-to-end.

◆Product listing by category — appetizer, rice meal, pasta, drink
◆Cart with product_id, quantity, price, special_request
◆Order type selection: delivery, pickup, dine_in, reservation
◆Order submission — creates Order{} with status: pending
◆Order status tracking page (pending → preparing → ready → completed)
◆Skip re-entry of info for logged-in customers
Testable by Logged-in customers can browse, order, and track their order status.
3
Sprint 03 · Weeks 5–6
Guest Customer Flow
User type

Guest ordering is a distinct UX path with its own confirmation stage. Build it now so cashiers handle both customer types before the POS is added.

◆Guest order form — first_name, last_name, phone, address saved to localStorage
◆Guest can edit info before checkout
◆Guest order submitted with customer_id: null
◆"Call Confirmation" stage added to guest order status flow
◆Cashier-side view to see pending guest orders needing confirmation
◆Cashier marks order confirmed → status advances to preparing
Testable by Cashiers can receive, call-confirm, and process guest orders alongside registered ones.
4
Sprint 04 · Weeks 7–8
Cashier POS & Transactions
Operations

The full cashier interface — walk-in transactions, payment processing, offline capability with sync, and receipt generation.

◆Cashier login with cashier_id, username, password
◆POS interface for walk-in dine-in, pickup, and delivery orders
◆Payment method selection: cash, GCash, card
◆Transaction record creation — Transaction{} schema
◆Offline POS mode — queue transactions locally
◆Sync queued offline transactions when back online
◆Receipt generation (printable or digital)
◆Cashier online/offline status toggle — isOnline
Testable by Cashiers can complete full POS transactions — online and offline — and generate receipts.
5
Sprint 05 · Weeks 9–10
Kitchen Dispatch & Order Status
Operations

Connect the kitchen to the order system. Real-time status updates flow from kitchen back to cashiers and customers.

◆Kitchen-side order ticket display (grouped by order type)
◆Kitchen marks orders: pending → preparing → ready
◆Delivery orders advance to: out_for_delivery → completed
◆Cancelled order handling and kitchen notification
◆Real-time order status visible to customers on their tracking page
◆Cashier dashboard reflects live kitchen status per order
Testable by Kitchen staff, cashiers, and customers all see the same live order status.
6
Sprint 06 · Weeks 11–12
Owner Dashboard & CMS
Admin

Give the owner full control — accounts, products, promos, and the storefront appearance. The CMS is the owner's day-to-day tool.

◆Owner login and protected admin routes
◆Create and manage cashier accounts — Cashier{} schema
◆Product management — add, edit, toggle isAvailable, update stock
◆Promo management — create Promo{}, set dates, discount rate, toggle isActive
◆Appearance tab — edit homepage content, banners, featured items
◆Performance tab — basic product performance view (orders per product)
Testable by Owner can manage the full system — staff, menu, promos, and storefront — without developer help.
7
Sprint 07 · Weeks 13–14
Analytics, Notifications & Polish
Launch-ready

Meaningful only once real transaction data exists. This sprint turns usage data into insight and keeps customers in the loop.

◆Sales reports and transaction logs for owner
◆Analytics dashboard — revenue, top products, order volume trends
◆Email/SMS notification system for registered customers
◆Promo notifications — triggered when isActive promo goes live
◆Bulk order availability and seasonal event announcements
◆UI/UX polish based on staff and customer feedback from sprints 1–6
◆Performance audit, error handling, and pre-launch QA
Testable by Owner sees actionable reports. Customers receive real notifications. System is launch-ready.
